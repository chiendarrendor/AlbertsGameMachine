## Outpost-specific

Surfaced 2026-09-18 while modernizing `Outpost/tca/Makefile`'s dependency tracking (see [[build-environment]] and the root TODO's Makefile-depend item) — `outposttest` doesn't currently build cleanly from scratch in this environment for three independent, pre-existing reasons, none related to that dependency-tracking work itself:

- [ ] `outposttest`'s target lists `${TESTOBJS}` before `${ARTIFACTOBJS}` in its prerequisites, but several test files (`../tests/StateMachineBidTest.cpp` at least) directly `#include "OutpostGameInfo.hpp"`, which is only generated as a side effect of building `${ARTIFACTOBJS}` (via the `${TCOM}` rule on `../OutpostServer.xml`). Building from a truly clean slate (`make clean && make outposttest`) fails because the header doesn't exist yet when the test objects are built first; a partial rebuild that already has the generated header lying around masks this ordering hazard.
- [ ] `Outpost/tca/Makefile` links against `-lboost_serialization-mt`/`-lboost_unit_test_framework-mt`, but this box's Boost packages don't ship `-mt`-suffixed library names (confirmed — `MerchantOfVenus/tca/Makefile` already accounts for this with plain `-lboost_serialization` etc.), so the final link always fails here.
- [ ] Genuine compile error in the transitioncompiler-generated `OutpostGameInfo.hpp`: `OutpostGameInfo::UnCommaStringify()`'s template body calls `UnComma()` with no declaration visible beforehand, which newer GCC's stricter two-phase template name lookup rejects (`there are no arguments to 'UnComma' that depend on a template parameter, so a declaration of 'UnComma' must be available [-fpermissive]`). Needs either a `-fpermissive` compile flag or a fix to whatever `transitioncompiler` template generates this pattern (worth checking whether `MerchantOfVenusGameInfo.hpp` has the same latent issue, since it's generated by the same tool).
